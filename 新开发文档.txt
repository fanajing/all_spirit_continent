1. 项目背景与目标

1.1 核心痛点

· 组合爆炸：随着模组内武魂与魂兽数量增加，手动编写魂技的工作量呈指数级增长。
· 外部模组兼容：玩家安装其他模组时，原版预设无法覆盖新增生物。
· 服务器成本：中心化AI接口随玩家增多费用极高。
· 数据污染风险：社区共享模式下，恶意或劣质魂技可能上传污染公共库。
· 审核压力：作者无法在游戏内逐条审核所有上传内容，需依靠社区自治+外部工具辅助。

1.2 核心目标

构建一套 “众包式、双阵营、带熔断机制的AI魂技生成系统” ，并配套 “社区评分 + 算法分流 + 外部审核” 的质量过滤体系。作者审核工作通过独立的EXE程序完成，不写入模组代码。

4. 魂技质量分级体系（三池分流 + 待确认标记）

4.1 四池定义与流转规则（作者审核外部化）

池名 代码 准入条件 抽取权重 流转规则
臻品池 ZHEN_PIN 平均分 ≥ 4.0 且 评价数 ≥ 3 高（×3） 评分低于3.5时降级至品鉴池
品鉴池 PIN_JIAN 上传时间 < 7天 或 评分 2.5~3.9 标准（×1） 7天后按评分升降级
凡品池 FAN_PIN 评分 < 2.5 低（×0.3） 永不自动升级
待确认池 PENDING reject_votes ≥ 5 且 差评率 > 60% 不出现在抽取中 仅标记，由外部EXE程序处理

关键变更：待确认池的魂技仅被标记为 PENDING，模组在抽取时直接忽略它们。最终处理（恢复/删除）由作者通过外部EXE程序操作OSS完成。

4.2 分流算法（模组侧）

玩家吸收魂环时：

1. 根据 (武魂+怪物注册名+血量档位) 查询云端。
2. 过滤掉 pool == "PENDING" 的条目。
3. 按权重从三池中随机抽取：
   ```text
   总权重 = (臻品池数量 × 3) + (品鉴池数量 × 1) + (凡品池数量 × 0.3)
   ```
4. 若无候选，触发AI生成 → 默认进入品鉴池（新品保护期）。

5. 核心交互流程（玩家视角）

5.1 吸收确认GUI（含一体化评分）

玩家右键吸收魂环后，弹出确认界面，布局如下：

UI 元素 内容 说明
标题 §6【第 X 魂环 · 魂技感应】 X为当前环位（1-9）
魂技名称 碎颅腐锤 取自AI生成或云端数据
效果描述 蓄力重击，造成范围伤害与尸毒。 展示描述
效果预览（数值） 伤害: 5.0 (范围 3格) / 饥饿 5秒 从execution解析
来源信息 §7上传者: 匿名魂师 · 评分: 4.2星 (12人评价) 云端已有数据时显示
按钮1 §a【吸收此魂技】 确认吸收，魂环绑定该技能
按钮2 §c【拒绝此魂技】 放弃吸收，魂环不消耗，魂兽白打
按钮3（条件显示） §b【自行推演】 跳过云端数据，强制AI重新生成（需有API可用），结果仅本地缓存不上传
评分区（吸收流程结束后显示） §7评价此魂技： [1星] [2星] [3星] [4星] [5星] 吸收成功或拒绝后，同一界面下方出现评分按钮，点击即提交，不额外弹窗

流程说明：

1. 玩家点击【吸收】或【拒绝】后，界面不关闭，而是动态切换为评分模式（隐藏三个主按钮，显示五个星星按钮）。
2. 玩家点击1-5星完成评分，界面关闭，流程结束。
3. 若玩家10秒内未评分，界面自动关闭，本次不记录评分（不强制）。

5.2 后续评分指令（用环位定位）

玩家吸收魂技时若未评分，或后续改变主意，可通过指令补充评分。指令直接使用“第几魂环”定位，无需记忆UUID。

指令 作用 示例
/douluo rate <环位> <1-5> 给指定魂环位的技能评分 /douluo rate 3 4 → 给第三魂环的技能评4星
/douluo rate <环位> cancel 取消该环位已有评分（撤回） /douluo rate 3 cancel

实现细节：

· 玩家的每个魂环位绑定一个 uuid（云端技能ID），存储在 player_config.json 中。
· 执行指令时，根据环位读取对应 uuid，再向云端提交评分。
· 若该环位为空或未绑定任何技能，提示 §c[斗罗] 该魂环位暂无魂技。

5.3 评分投票机制

· 1-2星 → reject_votes += 1（差评累积）
· 3星 → 中性，不计入差评
· 4-5星 → 计入 rating_sum 和 rating_count
· 防刷机制：同一玩家对同一个 uuid 的魂技，24小时内仅可评分一次。若重复评分，提示 §7[斗罗] 您24小时内已评价过此魂技。

9. 作者外部EXE程序（独立工具）

9.1 职责范围

该EXE程序不属于模组代码，由作者独立开发，直接读写阿里云OSS上的 public_skills.json 文件。功能包括：

· 拉取待确认池：筛选 pool == "PENDING" 的所有魂技，列表展示。
· 查看详情：展示魂技完整JSON、评分统计、差评明细。
· 批准恢复：将魂技从 PENDING 移回 PIN_JIAN，并重置 reject_votes = 0，rating_sum = 0，rating_count = 0（给予第二次机会）。
· 永久删除：从云端彻底移除该魂技。
· 组合拉黑：将特定 (武魂+怪物注册名) 组合加入黑名单，模组侧在生成时若检测到该组合被拉黑，直接拒绝生成并提示“该组合已被大陆法则封印”。

9.2 与模组的协作方式

· 模组侧：仅负责标记 pool = "PENDING"，不处理任何审核逻辑。
· EXE侧：直接操作OSS JSON文件，修改 pool 字段或删除条目。
· 同步机制：模组每次查询云端时，获取的是EXE处理后的最新数据。

11. 验收标准

1. GUI交互：吸收魂环时界面正常弹出，点击【吸收】后界面切换为评分星标，点击星星提交评分并关闭界面；10秒未操作自动关闭。
2. 指令评分：/douluo rate 3 4 能正确给第三魂环的技能评4星，且在24小时内重复执行有防刷提示。
3. 分流验证：运行100次抽取，臻品池被抽中次数显著高于凡品池。
4. 评分生效：评1星后 reject_votes+1，达到阈值后自动进入 PENDING 池，且不再出现在常规抽取中。
5. 外部审核联动：作者通过EXE将某魂技从 PENDING 恢复为 PIN_JIAN 后，模组下次查询时该魂技重新进入抽取池。
